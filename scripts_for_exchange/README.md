# Автоматическое создание почтовых ящиков Exchange (по расписанию, раз в час)

Это решение закрывает ограничение приложения AD-Ruby: приложение не может само
создать «настоящий» почтовый ящик Exchange (с `msExchMailboxGUID` в хранилище —
это делает только `Enable-Mailbox` на сервере Exchange). Скрипт
`enable_mailboxes.ps1` запускается на самом Exchange-сервере **по расписанию
(Task Scheduler, раз в час)**, находит новых пользователей без реального ящика
и создаёт им ящики.

## Что делает скрипт

1. Сканирует поддерево базового дерева AD (там приложение создаёт юзеров).
2. Отбирает **включённые** учётные записи `user/person`, у которых **нет
   `msExchMailboxGuid`** (реального ящика в БД ещё нет) — отбор через ADSI,
   поэтому не зависит от «витринных» атрибутов, которые приложение пишет напрямую.
3. Исключает OU уволенных сотрудников и служебные (технические) учётки.
4. Ограничивает список **пользователями, созданными за последние 8 часов**
   (`whenCreated`, параметр `-MaxAgeHours`) — т.е. только «свежие» аккаунты.
5. **Выводит список** найденных пользователей (логин, e-mail, дата создания, OU)
   и предлагает выбрать, кому включать ящик.
6. Для выбранных вызывает `Enable-Mailbox`:
   - БД почтового хранилища и сервер Exchange,
   - `Alias` = sAMAccountName (логин),
   - primary SMTP из primary SMTP-домена (если уже есть `SMTP:` в proxyAddresses — берёт его),
   - добавляет secondary из secondary SMTP-домена.
7. Пишет лог в файл **рядом со скриптом** (`enable_mailbox.log`).

Скрипт **идемпотентен**: уже созданные ящики (с `msExchMailboxGuid`) на следующем
запуске пропускаются — безопасно запускать каждый час.

## Интерактивный выбор пользователей

При ручном запуске скрипт показывает таблицу найденных пользователей и
спрашивает:

```
1) Включить почтовый ящик для ВСЕХ найденных? [Y/n]
```

- **Enter / Y / all** — включить ящики для всех.
- **Номер/логин сразу** (например `3` или логин) — включить ящик только этому
  пользователю.
- **N** — тогда скрипт предложит выбрать:
  ```
  2) Для ВКЛЮЧЕНИЯ введите номера и/или логины через запятую/пробел (можно диапазон 1-5).
     'all' — все, 'none' — никого. Пример: '1,3,<логин>,5' или просто '<логин>' (один пользователь).
  ```
  - `1,3,5` / `1 3 5` / `1-5` — только перечисленные номера,
  - `<логин1>,<логин2>` — только указанные логины,
  - `<логин>` — **только один конкретный пользователь**,
  - `none` — не включать никого (ничего не создаётся).

Для **запуска по расписанию** (без ручного ввода) обязательно используйте ключ
`-NoPrompts` — тогда скрипт обрабатывает **всех** найденных без вопросов.
Если нужно в расписании обработать только некоторых — задайте ключи
`-Include` / `-Exclude`.

## Установка и проверка (один раз, на сервере Exchange)

1. Скопируйте `enable_mailboxes.ps1` (и `infrastructure.yml` рядом с ним) на
   сервер Exchange, например в каталог `<каталог со скриптом>\`.

2. Откройте **Exchange Management Shell** (иконка «Exchange Management Shell»)
   на сервере Exchange от пользователя с правами Exchange
   Administrator (учётка Exchange-админа).

3. Пройдите проверку в режиме «что будет сделано» (ничего не создаёт):
   ```powershell
   cd <каталог со скриптом>
   .\enable_mailboxes.ps1 -WhatIf
   ```
   Вы увидите список логинов, для которых будет создан ящик. Убедитесь, что
   среди них только нужные пользователи (не уволенные, не тех. учётки).

4. Выполните реальный запуск разово (для проверки):
   ```powershell
   .\enable_mailboxes.ps1
   ```
   Проверьте лог `enable_mailbox.log` (рядом со скриптом): строки `[OK]` / `[FAIL]`.

## Настройка расписания (раз в час) — Task Scheduler

1. На сервере Exchange откройте **Task Scheduler** (`taskschd.msc`).
2. **Create Task…** → вкладка **General**:
   - Name: `Enable AD-Ruby Mailboxes`
   - «Run whether user is logged on or not»
   - «Run with highest privileges»
   - **Configure for**: выберите вашу версию Windows Server.
3. Вкладка **Triggers** → **New…**:
   - Begin the task: `On a schedule`
   - Settings: **Daily**, Time: когда угодно (например 00:00)
   - **Repeat task every `1 hour`** with duration `Indefinitely`
   - Enabled.
4. Вкладка **Actions** → **New…**:
   - Action: `Start a program`
   - Program/script: `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`
   - Add arguments:
     ```
     -NoProfile -ExecutionPolicy Bypass -Command "& '<путь к RemoteExchange.ps1>'; .\enable_mailboxes.ps1 -NoPrompts"
     ```
     *(при необходимости укажите полный путь к `enable_mailboxes.ps1`, например
     `& '<каталог со скриптом>\enable_mailboxes.ps1' -NoPrompts`)*
   - Start in: `<каталог со скриптом>`

   > **Важно:** в расписании обязательно добавляйте `-NoPrompts`, иначе скрипт
   > будет ждать ввода с консоли и задача зависнет. Без этого ключа он обработает
   > всех найденных пользователей автоматически.

5. Вкладка **Conditions**:
   - снимите «Start the task only if the computer is on AC power»,
   - снимите «Wake the computer to run this task» — не нужно.
6. Вкладка **Settings**:
   - отметьте «Run task as soon as possible after a scheduled start is missed».
7. Вкладка **General** — задайте учётную запись, под которой выполнять:
   рекомендуется **отдельная сервисная учётка** с правами Exchange Administrator
   («Organization Management» или эквивалент), а не личная.
   Пароль задайте в поле «Password».
8. **OK** → введите пароль учётки → задача создана.

> Если используете личную учётку админа Exchange — следите за её сменой пароля
> (нужно будет обновить её в задаче).

## Полезные параметры

```powershell
# Проверка без изменений (покажет список + выбор, но ничего не создаст)
.\enable_mailboxes.ps1 -WhatIf

# Без вопросов — обработать всех найденных (для расписания)
.\enable_mailboxes.ps1 -NoPrompts

# Показать пользователей, созданных за последние 24 часа
.\enable_mailboxes.ps1 -MaxAgeHours 24

# Включить ящик только для отдельных логинов
.\enable_mailboxes.ps1 -Include "<логин1>,<логин2>"

# Исключить отдельных логинов (остальные — создать)
.\enable_mailboxes.ps1 -NoPrompts -Exclude "<логин1>,<логин2>"

# Только конкретная OU
.\enable_mailboxes.ps1 -SearchBase "<база OU>"

# Другой файл лога
.\enable_mailboxes.ps1 -LogPath "<каталог со скриптом>\EnableMailbox.log"
```

> `-Include` и `-Exclude` принимают логины через запятую или пробел.
> `-Include` имеет приоритет над `-Exclude`. Если задан `-Include`, то всегда
> используется он (интерактивный выбор не показывается).

## Частые ошибки

| Ошибка | Причина / решение |
|---|---|
| `Enable-Mailbox` не найден | Скрипт запущен не в Exchange Management Shell. Подключите модуль (`RemoteExchange.ps1`) или запускайте из EMS. |
| `Access is denied` при `Enable-Mailbox` | Учётке не хватает прав. Дайте роли «Mail Recipients» / «Organization Management». |
| Пользователь пропал из списка после первого запуска | Нормально: у него появился `msExchMailboxGuid`, повторно ящик не создаётся. |
| `Эта задача не поддерживает получателей такого типа ... тип UserMailbox` | У пользователя уже стоят «фантомные» атрибуты от приложения (`msExchRecipientTypeDetails=1`). Скрипт теперь снимает их (`Clear-MailboxPreviewAttrs`) перед `Enable-Mailbox` — повторный запуск должен пройти. |
| В списке у пользователя показывается вторичный SMTP вместо primary | Приложение сохранило вторичный адрес раньше первичного. Скрипт теперь выбирает первичный адрес регистрозависимо (только прописной `SMTP:`), поэтому вторичный адрес не «перебивает» основной. |
